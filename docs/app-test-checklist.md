## 1. 音频通路（最高风险）

改了什么：音频从「主进程隐藏引擎窗口」改回渲染进程的 `<audio>`；移除低内存模式；
`<audio>` 被**无条件**设了 `crossOrigin = 'anonymous'`；打开沉浸页时会建 Web Audio 图。

### 1.1 三种音源都要能播（对应 `crossOrigin` 的全局影响）

`crossOrigin='anonymous'` 是全局生效的：某个音源如果响应缺 `Access-Control-Allow-Origin`，
后果不是「没频谱」而是**彻底加载失败**。三处音源已于改造中核实/补齐，但要以实机为准：

| #   | 场景                                             | 预期                                    |
| --- | ------------------------------------------------ | --------------------------------------- |
| 1   | 在线播放（未下载的歌，走网易云 CDN 直链）        | 有声；进度条走动；不出现 media 加载错误 |
| 2   | 播放已下载到本地的歌（`muice-file://`）          | 同上                                    |
| 3   | 播放命中缓存的歌（`muice-cache://`，**主路径**） | 同上                                    |

**怎么看失败**：Console 里会有 `Cross-Origin Resource Sharing` / `MEDIA_ELEMENT_ERROR` 之类，
且**歌直接放不出来**（不是静音、是加载失败）。任何一条失败都要立刻停下来报给我。

### 1.2 建图前后的行为一致（`createMediaElementSource` 是不可逆的）

Web Audio 图在**第一次打开沉浸页**时建立（普通列表页不建）。元素一旦进图，声音只从图里出来。

| #   | 操作                                                  | 预期                                     |
| --- | ----------------------------------------------------- | ---------------------------------------- |
| 4   | 普通页面播放 → 进沉浸页                               | 声音**不中断**，不静音，不重头开始       |
| 5   | 沉浸页里：暂停 / 播放 / 切歌 / 拖进度条 / 点歌词 seek | 全部正常，无静音、无爆音、无加速减速     |
| 6   | 沉浸页 → 退出到普通页面                               | 声音继续，不中断                         |
| 7   | 连续开关沉浸页 5 次以上                               | 仍然有声（幂等，不应出现第二次建图失败） |

### 1.3 输出设备切换（建图前 / 建图后走的是两条不同路径）

| #   | 操作                                                 | 预期                                          |
| --- | ---------------------------------------------------- | --------------------------------------------- |
| 8   | **未打开过沉浸页**时切换输出设备（设置里的播放设备） | 声音从新设备出                                |
| 9   | 打开沉浸页（建图完成）后切换输出设备                 | 声音从新设备出（走 `AudioContext.setSinkId`） |
| 10  | 再退出沉浸页，切回又一个设备                         | 仍从新设备出（设备选择在两条路径间不丢）      |
| 11  | 切到一个「已拔出的设备 / 不存在的设备」              | 不崩溃；要么回退要么提示，不能整个应用没声音  |

> 若第 8–10 项某一项失败：告诉我「当时是否打开过沉浸页」，这能直接定位是
> `HTMLMediaElement.setSinkId` 路径还是 `AudioContext.setSinkId` 路径。

### 1.4 低内存模式确认移除

| #   | 操作                        | 预期                                                            |
| --- | --------------------------- | --------------------------------------------------------------- |
| 12  | 沉浸设置面板逐个 tab 翻一遍 | **不再有**「低内存模式」相关开关                                |
| 13  | 播放中打开任务管理器        | 不应再有额外的隐藏渲染窗口/主进程引擎残留；CPU 占用没有异常翻倍 |

### 1.5 已知情况（**不是 bug**，别当缺陷报）

- **频谱现在唯一的消费者是「几何」背景。** `AudioBands`（真实频谱）已在皮肤上下文里就绪
  （`SkinContext.bands()`），但两款皮肤都还没用它画东西 —— 只有背景类型选「几何」时，
  形状才会按频带缩放（见 §6）。其余背景下 Web Audio 图仍是「建好、暂无消费者」。
  也就是说：**不选「几何」背景时，第 1 节建的图是白建的**，这是当前预期状态。

## 5.1 设置的归属：只有一份（属于「经典」），倾诉没有设置

**设置只有一份，它属于「经典」面板。** store 是**扁平**的（`{ ...createDefaultSettings(), skin }`），
没有按面板分桶、没有第二个「编辑目标」；持久化 `pick` = 默认设置的全部键 + `skin`。
「倾诉」**没有设置**：背景恒为「几何」且不可改、永不显示封面、歌词排版与字体用内置值，
只沿用少数沉浸页通用项（明暗主题 / 专辑主色 / 底栏四项 / 演示模式 / 歌词偏移，读的是同一份）。

> 历史注记：皮肤系统刚上线时曾短暂按面板分桶（`panels: Record<SkinId, ImmersiveSettings>`），
> 也已试过「按面板裁剪设置行」（`settings/panel-capabilities.ts`）—— 两者均已被用户否决并删除；
> 歌词 tab 是**合并回来的完整一套**（`settings/LyricTab.vue` 单一版本）。

**倾诉不显示设置按钮**：判据是 `SkinDefinition.hasSettings`（`skins/types.ts`；经典 true、倾诉 false），
由 `skins/shared/SkinShell.vue` 决定；主题切换胶囊在倾诉下**占住设置按钮那一格**。

## 6. 几何背景（新增的第 6 种背景类型）

来源是 Folia 的背景层（`GeometricBackground.tsx`）：底色之上 15 个缓慢漂移自转的几何形状、
20 个上浮粒子与一层径向暗角。**与 Folia 的差异见 §6.1**（全属刻意为之，不是缺陷），
其中最要紧的三处：随机源换成按歌曲 id 的确定性种子（同一首歌每次进来形状都一样，不会跳）；
不做 JS 弹簧，频带缩放走 CSS `transition`；漂移/自转交给 CSS keyframes 而不是逐帧写内联样式。

| #   | 操作                                                                                                         | 预期                                                                                                     |
| --- | ------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------- |
| 61  | 设置 →「背景」tab 的「类型」选「几何」                                                                       | 立即出现形状与粒子；类型一行现在有 6 个选项（流体/模糊/渐变/**几何**/纯色/无）                           |
| 62  | 反复「几何」↔「纯色」来回切 5 次                                                                             | 每次都正常出画面，不残留、不白屏、控制台无报错                                                           |
| 63  | 切歌 / 重进沉浸页                                                                                            | 同一首歌形状布局**不变**（确定性种子）；换一首歌才换一套                                                 |
| 64  | 播放时看形状                                                                                                 | 圆/方（低音）、三角（中音）、十字（高音）、图标（整体能量）各自**独立**缩放，随鼓点起伏                  |
| 65  | 暂停播放                                                                                                     | 形状缩回静止档（不再随音乐缩放）；漂移与自转**继续**（背景是环境层，定格反而像卡住）                     |
| 66  | 明暗主题切换（`colorScheme`）**含与 app 主题不一致的组合**（app 主题浅色 + 沉浸配色深色 = 曾经出问题的那次） | 背景自带专辑底色，形状/暗角/文字对比正常；不会出现「浅底上看浅形状」（这条修过一次，2026-10-10）         |
| 67  | 换歌换封面                                                                                                   | **整层底色**（专辑遮罩色，与「纯色」背景同色）+ 形状色 + 粒子/暗角色一起跟着变                           |
| 68  | 窗口缩到很窄 / 拉很大                                                                                        | 背景铺满、不出现横向滚动条、形状不溢出到可视区外                                                         |
| 69  | 系统开启「减少动态效果」                                                                                     | 漂移与粒子停止，静态构图仍在（不是整块消失）                                                             |
| 70  | 性能                                                                                                         | 与「流体」背景比 CPU/GPU 占用应更低；不支持 `scale`/`translate` 独立属性的旧内核下形状仍在（只是不缩放） |

> 第 64 条需要能听出高低音的歌（鼓点明显的）。若完全不动，先确认背景类型确实是「几何」，
> 再报给我 —— 频带通路的排查要看 `AudioBands`。

### 6.1 与 Folia 的已知差异（**不是缺陷**，别报）

| 项       | Folia                               | 本项目                                                                | 原因                                                          |
| -------- | ----------------------------------- | --------------------------------------------------------------------- | ------------------------------------------------------------- |
| 随机性   | `Math.random()`，每次进页面都换一套 | 按歌曲 id 的确定性种子                                                | 进页面/切皮肤/暂停时形状不该「跳一下」                        |
| 底色     | 几何层透明，铺在 app 主题底色上     | 几何层自铺专辑遮罩底色（`--rnp-accent-color-bg`，与「纯色」背景同源） | 本项目沉浸层明暗与 app 主题相互独立，不能假定底色与文字色同源 |
| 频带平滑 | framer-motion `useSpring`           | CSS `transition: scale 0.12s linear`                                  | 频带本就每帧刷新，再加 JS 弹簧只是多一层延迟                  |
| 形状驱动 | JS 逐帧写内联样式                   | CSS keyframes 驱动漂移/自转                                           | 不与 60fps 流体背景抢性能预算                                 |
| 暂停行为 | 冻结漂移                            | 漂移继续，只有频带缩放回落                                            | 背景定格看起来像卡住                                          |
| 暗角末色 | 恒 `rgba(0,0,0,.6)`                 | `--rnp-accent-color-overlay`（浅色主题下是白）                        | 浅色主题下用黑色暗角会「白底被压黑一圈」                      |
