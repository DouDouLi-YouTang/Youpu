## 1. 音频通路（最高风险）

改了什么：音频从「主进程隐藏引擎窗口」改回渲染进程的 `<audio>`；移除低内存模式；
`<audio>` 被**无条件**设了 `crossOrigin = 'anonymous'`；打开沉浸页时会建 Web Audio 图。

### 1.1 三种音源都要能播（对应 `crossOrigin` 的全局影响）

`crossOrigin='anonymous'` 是全局生效的：某个音源如果响应缺 `Access-Control-Allow-Origin`，
后果不是「没频谱」而是**彻底加载失败**。三处音源已于改造中核实/补齐，但要以实机为准：

| # | 场景 | 预期 |
|---|---|---|
| 1 | 在线播放（未下载的歌，走网易云 CDN 直链） | 有声；进度条走动；不出现 media 加载错误 |
| 2 | 播放已下载到本地的歌（`muice-file://`） | 同上 |
| 3 | 播放命中缓存的歌（`muice-cache://`，**主路径**） | 同上 |

**怎么看失败**：Console 里会有 `Cross-Origin Resource Sharing` / `MEDIA_ELEMENT_ERROR` 之类，
且**歌直接放不出来**（不是静音、是加载失败）。任何一条失败都要立刻停下来报给我。

### 1.2 建图前后的行为一致（`createMediaElementSource` 是不可逆的）

Web Audio 图在**第一次打开沉浸页**时建立（普通列表页不建）。元素一旦进图，声音只从图里出来。

| # | 操作 | 预期 |
|---|---|---|
| 4 | 普通页面播放 → 进沉浸页 | 声音**不中断**，不静音，不重头开始 |
| 5 | 沉浸页里：暂停 / 播放 / 切歌 / 拖进度条 / 点歌词 seek | 全部正常，无静音、无爆音、无加速减速 |
| 6 | 沉浸页 → 退出到普通页面 | 声音继续，不中断 |
| 7 | 连续开关沉浸页 5 次以上 | 仍然有声（幂等，不应出现第二次建图失败） |

### 1.3 输出设备切换（建图前 / 建图后走的是两条不同路径）

| # | 操作 | 预期 |
|---|---|---|
| 8 | **未打开过沉浸页**时切换输出设备（设置里的播放设备） | 声音从新设备出 |
| 9 | 打开沉浸页（建图完成）后切换输出设备 | 声音从新设备出（走 `AudioContext.setSinkId`） |
| 10 | 再退出沉浸页，切回又一个设备 | 仍从新设备出（设备选择在两条路径间不丢） |
| 11 | 切到一个「已拔出的设备 / 不存在的设备」 | 不崩溃；要么回退要么提示，不能整个应用没声音 |

> 若第 8–10 项某一项失败：告诉我「当时是否打开过沉浸页」，这能直接定位是
> `HTMLMediaElement.setSinkId` 路径还是 `AudioContext.setSinkId` 路径。

### 1.4 低内存模式确认移除

| # | 操作 | 预期 |
|---|---|---|
| 12 | 沉浸设置面板逐个 tab 翻一遍 | **不再有**「低内存模式」相关开关 |
| 13 | 播放中打开任务管理器 | 不应再有额外的隐藏渲染窗口/主进程引擎残留；CPU 占用没有异常翻倍 |

### 1.5 已知情况（**不是 bug**，别当缺陷报）

- **频谱目前没有任何一处渲染它。** `AudioBands`（真实频谱）已在皮肤上下文里就绪
  （`SkinContext.bands()`），但「经典」和「倾诉」两款皮肤都还没用它画东西。
  也就是说第 1 节的 Web Audio 图现在只承担「建好、但暂无消费者」的角色。
  要不要给某款皮肤加个频谱视觉元素，等你测完再定。

## 3. 「经典」面板：零回归

「经典」= 改造前的布局（样式是从外壳原样搬过去的，选择器与声明一字未改，已做过机械比对）。
所以这里**只要发现任何视觉差异，都是回归**：

| # | 检查项 | 预期 |
|---|---|---|
| 19 | 左侧封面位置 / 大小 / 圆角、右侧歌词居中与行距 | 和你印象中的改造前**完全一致** |
| 20 | `display-mode` 三档：all / 仅歌词 / 仅封面 | 三档布局与改造前一致 |
| 21 | 封面 4 组对齐设置（居左/居中 × 居下/居中） | 与改造前一致 |
| 22 | 歌词区七种动画（缩放/模糊/淡入/错位/旋转/卡拉OK/辉光）逐个开关 | 都与改造前一致 |
| 23 | 歌词点击 seek、贡献者显示三态 | 与改造前一致 |

> 想快速对照：`git stash` 掉未提交改动、或 `git checkout 146e938` 跑一次截图，再切回来比。

## 4. 「倾诉」面板（新功能）

| # | 操作 | 预期 |
|---|---|---|
| 24 | 有逐字歌词的歌（多数歌走 YRC，都有） | 当前行按 1–4 段分行排布；每段各自浮现；倾斜段斜体 + 上下交错 |
| 25 | 逐字节奏 | 正在唱的字有轻微放大脉冲；唱过的字留一点「余晖」（略大且不回落为 0） |
| 26 | 暂停 | 动画**定格**（不能继续跑、也不能全部消失） |
| 27 | 恢复播放 | 从定格处继续，不跳帧、不重播整行 |
| 28 | 拖进度条到别处 / 切歌 | 立刻重排到当前行；**不能卡在上一行** |
| 29 | 歌词偏移（设置里调 `lyricOffset`） | 面板跟着偏移，不出现「面板比声音早/晚一行」的错位 |
| 30 | 点某一段歌词 | 跳到该行（seek 正确；偏移量与经典面板一致） |
| 31 | 长行（超过可用宽度） | 整体缩小以放下（最多缩到 50%/55%）；**极长**时改为重切成更多段 |
| 32 | 窗口缩放 | 字号随视口变化（clamp）；缩放后面板不溢出屏幕 |
| 33 | 演唱者/贡献者行 | 「倾诉」有意不渲染贡献者（设计如此），确认不会出现半截元素 |
| 34 | 无歌词 / 纯音乐 / 加载中 / 未选歌 | 分别显示：`歌词加载中…` / `纯音乐，请欣赏` / `暂无歌词` / `等待音乐` |
| 35 | 封面四组对齐设置（第 21 项的倾诉版） | **居中要真的居中**（本次刚修的点）；仅封面模式下也不能左移 |
| 36 | 仅歌词模式 | 封面隐藏，排版带用满宽度 |
| 37 | 字号设置（`lyricFontSize`）与自定义字体 | 倾诉面板跟着变（字号、字体族、字重都吃全局设置） |
| 38 | 播放速度 1.5× | **已知限制**：CSS 动画走墙钟时间，不随倍速缩放 —— 逐字脉冲会跟不上（经典面板的逐字过渡同样如此）。不作为缺陷记录 |
